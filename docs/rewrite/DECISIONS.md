## Инфраструктура и деплой (подробности — `DEPLOY.md`)
- [ ] **ВМ под новую систему** на текущем Proxmox: IP в 192.168.0.0/24 и размер (рекомендация: 2 vCPU, 3–4 ГБ RAM, 30–40 ГБ диска). Учтите: ВМ Kerio + АТС уже занимают 12 из 15 ГБ RAM хоста; после перехода старые Node-процессы на хосте (~0.9 ГБ) выключаются.
- [ ] **Домен**: оставить `uniconsoft.ddns.net`? (Тот же домен = старые passkeys продолжат работать.)
- [ ] **Порт 443 снаружи** сейчас занят админкой Kerio. Освободить его под новую систему (а админку Kerio — только из VPN/офиса)?
- [ ] **ADMIN_IPS** — с каких адресов разрешён SSH на новую ВМ (офис, VPN).
- [ ] **Кто подтверждает деплой** в GitHub (reviewers окружения `production`).
- [ ] **Куда хранить копии бэкапов** вне сервера (NAS, другой сервер, облако).
- [ ] **Репозиторий на GitHub публичный или приватный?** Для публичного нельзя использовать self-hosted runner для деплоя; кроме того, в истории репозитория лежит пароль AMI — его в любом случае надо сменить.
- [ ] Нужны ли после перехода процессы на хосте, которых нет в репозитории: `isabella-connector` (прокси на админку АТС, порт 3050), `telegram-form-dashboard` (Next.js), `call-center-tg-bridge` (Telegram → ИИ-агент)? Зависят ли они от API старой системы?
- [ ] Обновление Proxmox 7 → 8/9 и Debian 11 (вне поддержки), усиление Kerio — когда и кто.
